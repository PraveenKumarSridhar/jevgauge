Model capacity

Choose task model capacity. Prefer economical only for clearly bounded low-risk transformations; balanced for ordinary, vague, or mixed tasks; strongest when the task is demanding or a weak answer is costly.

economical: Clearly bounded low-risk transformation
balanced: Ordinary, vague or mixed task
strongest: Demanding or high cost of a weak answer

Reasoning depth

Choose reasoning depth independently of model capacity. Choose high only when multi-step reasoning materially matters.

low: Simple direct reasoning
medium: Ordinary analysis or planning
high: Demanding multi-step reasoning

Input: first 1,200 Python characters of the first substantive task prompt. Later turns and tool output are excluded. The displayed policy reason is not generated chain of thought.

What save means
Only supported settings are saved. Restart Hermes Desktop for new conversations to use them. Existing bindings and historical results stay unchanged. Configuration validity does not prove account eligibility.
Sources, assumptions and what is not measured
Captured evidence
Input includes cached input. Output includes reasoning tokens. Requests with missing usage or prices are excluded from cost comparisons, never treated as free. Request-count coverage does not bound missing dollars.
Dates include provider attempts that started in the selected period and route-only activity. Earlier routing evidence supplies historical defaults. The displayed timezone sets inclusive local date boundaries.
Pricing and comparisons
The same known-usage, non-manual cohort is repriced against each captured historical default, median eligible model and highest configured capability tier. Capability is configured ordering, not measured quality. No effort price multiplier is used.
Not measured
API-equivalent differences do not establish subscription bill reductions, causal savings or preserved task quality. Prompt text and credentials are not retained.
